# Ango — 指定ファイル/フォルダ暗号化アプリ

ファイル単位で公開鍵方式の暗号化と署名を行うコマンドラインツールです。

- 鍵は USB などの取り外し可能なデバイスだけで管理し、PC には残しません。
- USB が挿さっているときだけ、暗号化と復号ができます。
- 自分の鍵で署名するので、他人が作った偽の `.ang` や差し替えを見分けられます。
- 一度パスフレーズを入力すると、USB が挿さっている間は 30 分間入力を省けます（使うたびに延長）。
- ango の鍵の代わりに、GPG で作った鍵（USB 上の GNUPGHOME）も使えます。

## ビルド

必要なもの: CMake 3.16 以上、C++17 コンパイラ、libsodium（`brew install libsodium`）
GPG の鍵を使う場合は、実行時に GnuPG 2.1 以上（`gpg` コマンド）も必要です。

```sh
cmake -S . -B build
cmake --build build
sudo cmake --install build      # /usr/local/bin/ango にインストール（任意）
```

## コマンド一覧

| コマンド | 内容 |
|---|---|
| `ango keygen [出力フォルダ]` | 秘密鍵を作る（初回のみ。USB を指定する） |
| `ango gpg-setup フォルダ [鍵ファイル...] [鍵ID]` | ango の鍵の代わりに、USB 上の GPG の鍵を使うように設定する（鍵ファイルは取り込む） |
| `ango encrypt [オプション] パス...` | ファイル/フォルダを暗号化・署名する |
| `ango decrypt [オプション] パス...` | 署名を確かめて復号する |
| `ango key-location [パス \| --forget]` | 秘密鍵の場所を表示/設定/消去する |
| `ango lock` | 解錠キャッシュを消す（GPG の鍵では gpg-agent などを止める。次回はパスフレーズが必要） |
| `ango eject` | ロックしてから、鍵のある USB を取り外す |
| `ango --help` / `ango --version` | ヘルプ / バージョンを表示する |

### オプション

| オプション | 意味 |
|---|---|
| `-k`, `--keep` | 元のファイルを削除しない |
| `-f`, `--force` | 出力先が既にあれば上書きする |
| `-o`, `--open` | 復号後にファイルを開く（decrypt のみ） |
| `--allow-unsigned` | 署名のない旧形式のファイルも復号する（decrypt のみ。下の「旧バージョンからの移行」を参照） |

## 使い方

### 1. 鍵を作る（初回のみ）

```sh
ango keygen /Volumes/USB
```

- パスフレーズを 2 回入力すると、`ang_secret.key`（パスフレーズで暗号化した秘密鍵）が作られます。
  暗号化・署名・復号に使う鍵は、すべてこのファイル 1 つに入っています。
- USB に直接作るか、作成後に USB へ移して、PC には残さないでください。
- 鍵を作った USB のルートに `.metadata_never_index` を作り、Spotlight に索引を作らせないようにします
  （索引を作っている間は USB を取り外せないことがあるため）。

### 2. 暗号化

```sh
ango encrypt 書類.pdf             # → 書類.pdf.ang
ango encrypt 資料フォルダ          # → 資料フォルダ.tar.ang（tar でまとめてから暗号化）
ango encrypt *.txt                # 複数まとめて
```

- USB 上の秘密鍵を使います。パスフレーズは、解錠キャッシュが無いときだけ聞かれます。
- USB が挿さっていないときは「秘密鍵が見つかりません。USB を差してから、もう一度実行してください。」と
  表示し、何もしません。
- 暗号化に成功すると、元のファイル/フォルダは削除されます（`-k` で残せます）。
- シンボリックリンクは暗号化できません（リンク先を指定してください）。

### 3. 復号

```sh
ango decrypt 書類.pdf.ang            # → 書類.pdf
ango decrypt -o 資料フォルダ.tar.ang  # 同じ場所に展開して Finder で開く
```

- 先に署名を確かめます。自分の鍵で作ったものでなければ、何も書き出さずに中止します。
- 復号に成功すると `.ang` は削除され、平文のファイルが残ります。自由に編集でき、
  作業が終わったら `ango encrypt` で暗号化し直します（`-k` で `.ang` を残せます）。
- 同じ名前のファイルが既にあるときは中止します（`-f` で上書き）。

### 秘密鍵の場所

- PC に保存するのは秘密鍵の「場所」の情報だけで、鍵そのものは保存しません。
- 場所がまだ保存されていなければ（初回）、場所を尋ねます。
- 保存した場所に鍵が無いとき、暗号化は中止します。
  復号は場所を尋ねます（USB を挿してから Enter を押すと、同じ場所をもう一度確認します）。
- ターミナルでは、場所を尋ねられたときにファイルやフォルダをドラッグ&ドロップして入力できます。

### パスフレーズの入力を省く（解錠キャッシュ）

一度パスフレーズを入力すると、**最後に使ってから 30 分間**は入力を省けます（使うたびに延長されます）。

- 解錠した鍵を使い捨ての鍵 K で暗号化して USB 上（`ang_session`）に置き、K は PC 側に置きます。
  両方が揃ったときだけ使えます。
- USB を抜けば使えません。USB だけ盗まれても K が無いので開けません。
- PC を再起動すると無効になります。パスフレーズを入力するたびに新しい K を作ります。
- すぐにロックしたいときは `ango lock` を実行します（席を離れるときなど）。
- キャッシュが有効な間に、ログイン中の PC と USB を両方とも奪われると、パスフレーズなしで使われます。

### USB を取り外す

```sh
ango eject
```

- ロックしてから（GPG の鍵では gpg-agent などのプロセスも止めてから）、鍵のある USB を取り外します。
- 使用中で取り外せないときは 10 秒ほど再試行し、それでも駄目なら原因（使用中のプロセスなど）を表示します。
- ango や gpg が USB に書き込むたびに Spotlight が索引を作りに来て、その間は取り外せないことがあります。
  そのため `ango keygen` と `ango gpg-setup` は、USB のルートに `.metadata_never_index` を作って
  索引を作らないようにします（起動ディスクには作りません。すでにあれば何もしません）。
- このファイルが無いバージョンの ango で鍵を作った USB には、手で作れます:
  ```sh
  touch /Volumes/USB/.metadata_never_index
  ```
- macOS のバージョンによってはこのファイルが効かないことがあります。それでも取り外せないときは、
  次のコマンドでこの USB の索引作成を止めてください（初回のみ、管理者のパスワードが必要）:
  ```sh
  sudo mdutil -i off /Volumes/USB
  ```
  `mdutil -s /Volumes/USB` で「Indexing disabled.」と表示されれば、索引は作られません。

## GPG の鍵を使う

`ango keygen` で作る鍵の代わりに、GPG で作った鍵を使えます。RSA・ECC など鍵の種類は問いません。
GPG の鍵は USB 上の GNUPGHOME（gpg の鍵フォルダ）に置きます。

書き出した鍵ファイル（`gpg --export` / `gpg --export-secret-keys` で作った `.asc` など）がある場合は、
そのまま指定すれば USB へ取り込んで設定します。

```sh
ango gpg-setup /Volumes/USB/gnupg 公開鍵.asc 秘密鍵.asc
```

- フォルダが無ければ作ります。GNUPGHOME ではなく、ほかのファイルがあるフォルダ（`/Volumes/USB` など）を
  指定したときは、その中に `gnupg` フォルダを作って取り込みます。
- 候補になるのは今回取り込んだ秘密鍵だけです。公開鍵だけでは使えません。
- 取り込みが終わったら、元の秘密鍵のファイルはバックアップとして安全な場所へ移すか、削除してください。

USB 上に既に GNUPGHOME がある場合や、新しく鍵を作る場合:

```sh
# USB 上に GPG の鍵を作る（既にあれば不要）
mkdir -m 700 /Volumes/USB/gnupg
gpg --homedir /Volumes/USB/gnupg --quick-generate-key '名前 <メール>' default default never

# ango で使うように設定する
ango gpg-setup /Volumes/USB/gnupg            # 鍵が 1 つだけのとき
ango gpg-setup /Volumes/USB/gnupg 鍵ID       # 複数あるとき（フィンガープリント、メールアドレスなど）
```

- 暗号化と署名の両方に使える秘密鍵が必要です（`default default` で作ればそうなります）。
- `gpg-setup` は試しに暗号化・署名・復号を行って確かめ、GNUPGHOME に `ang_gpg.key`（使う鍵のフィンガープリント）を
  作ります。以後の暗号化・復号はこの鍵で行います。USB が無いときの動きは ango の鍵と同じです。
- パスフレーズは gpg-agent が覚えている間は聞かれません。覚えていなければ ango が端末かダイアログで尋ね、
  gpg に渡します（pinentry の設定は不要です）。覚えている時間は USB 上の `gpg-agent.conf` の
  `default-cache-ttl`（既定 600 秒）で変えられます。`ango lock` で gpg-agent・scdaemon などを止めて忘れさせます。
- USB を取り外すときは `ango eject` を使うと、gpg のプロセスを止めてから取り外します。
  `gpg-setup` も USB のルートに `.metadata_never_index` を作ります（「[USB を取り外す](#usb-を取り外す)」を参照）。
- USB を抜くと、gpg-agent が動いていても秘密鍵を読めないので、暗号化も復号もできません。
- gpg-agent のソケットは exFAT/FAT の USB には作れないため、ango は GNUPGHOME に転送ファイル（`S.gpg-agent` など）を置き、
  ソケットを PC の一時フォルダに作らせます（GnuPG の標準機能です。そのフォルダで gpg を直接使っても問題ありません）。
- GPG の鍵で作った `.ang` は ango の鍵では開けず、その逆も同じです。切り替えるには `ango key-location` で
  `ang_secret.key` か `ang_gpg.key` を指定します。
- Finder から使うとき、`gpg` は PATH に加えて `/opt/homebrew/bin`、`/usr/local/bin`、`/usr/local/MacGPG2/bin` から探します。
  別の場所にある場合は環境変数 `ANGO_GPG` で指定します。

## Finder から使う（macOS）

```sh
scripts/install_macos_apps.sh /usr/local/bin/ango
```

`~/Applications` に 2 つのアプリが作られます。

- **Ango 復号.app**: `.ang` ファイルをダブルクリックすると、復号して開きます。
  ダブルクリックで開かない場合は、`.ang` ファイルの「情報を見る」→「このアプリケーションで開く」で
  「Ango 復号」を選び、「すべてを変更」を押してください。
- **Ango 暗号化.app**: ファイルやフォルダをドロップするか、右クリック →「このアプリケーションで開く」→
  「Ango 暗号化」で暗号化します。

Finder から実行したときは、パスフレーズや鍵の場所をダイアログで尋ね、エラーもダイアログで表示します。

右クリックメニューの「クイックアクション」に直接出したい場合は、Automator で作成します。

1. Automator →「新規書類」→「クイックアクション」
2. 「ワークフローが受け取る現在の項目」を「ファイルまたはフォルダ」、検索対象を「Finder」にする
3. 「シェルスクリプトを実行」を追加し、入力の引き渡し方法を「引数として」にして、次のように書く
   ```sh
   /usr/local/bin/ango encrypt "$@"
   ```
4. 「Ango で暗号化」などの名前で保存する

## どこに何が置かれるか

| 場所 | ファイル | 内容 |
|---|---|---|
| USB | `ang_secret.key` | 秘密鍵（パスフレーズで暗号化） |
| USB | `ang_session` | 解錠キャッシュの片方（K が無いと開けない） |
| USB のルート | `.metadata_never_index` | Spotlight に索引を作らせないための空のファイル（`keygen` / `gpg-setup` が作る） |
| USB の GNUPGHOME | `ang_gpg.key` | 使う GPG の鍵のフィンガープリント（GPG の鍵を使う場合） |
| USB の GNUPGHOME | `S.gpg-agent` など | gpg-agent のソケットの転送先（GPG の鍵を使う場合） |
| PC `~/Library/Application Support/ang/` | `secret_key_location` | 秘密鍵（または `ang_gpg.key`）の場所（パスのみ） |
| PC `~/Library/Application Support/ang/` | `session` | 解錠キャッシュの K と有効期限 |

## 暗号の仕組み

- ファイルごとにランダムな鍵を作り、XChaCha20-Poly1305 で 64KB ずつ暗号化します（libsodium の secretstream）。
- そのファイル鍵を、自分の公開鍵（X25519）宛てに暗号化してヘッダーに入れます（sealed box）。
- ヘッダーに Ed25519 で署名します。署名鍵は秘密鍵から導出するので、別のファイルとしては保存しません。
  本文はヘッダー内のファイル鍵でしか作れないため、ヘッダーへの署名で本文も作成者に結び付きます。
- 秘密鍵ファイルは、パスフレーズから Argon2id で作った鍵で暗号化しています。
- 改ざんや途中で切れたファイルは検出され、復号は中止されます（作りかけの出力も消します）。
  フォルダ（`.tar.ang`）は一時フォルダに展開し、検証が通ってから元の場所へ移します。
- GPG の鍵の場合（形式 v3）、本文の暗号化は同じで、ファイル鍵を `gpg --encrypt` で暗号化し、ヘッダーに
  `gpg --detach-sign` で署名します。復号の前に、署名が設定した鍵（主鍵のフィンガープリント）のものであることを確かめます。

## 旧バージョンからの移行

v0.1.0（署名機能を入れる前）を使っていた場合:

- 秘密鍵 `ang_secret.key` は、そのまま使えます。
- v0.1.0 で作った `.ang` には署名がないため、そのままでは復号できません。自分で作ったものに間違いなければ、
  `ango decrypt --allow-unsigned ファイル.ang` で復号し、暗号化し直してください（署名付きになります）。
- `~/Library/Application Support/ang/public.key` と `ang_public.key` は不要になったので、削除して構いません。

## 注意点

- **復号したファイルは平文のままディスクに残ります。** 使い終わったら暗号化し直してください。
- 暗号化後に元のファイルを削除しますが、SSD や APFS では、削除したデータが確実に消える保証はありません。
  機密性の高いデータは、作成後すぐに暗号化して、平文の期間を短くしてください。
- 本物の `.ang` 同士の名前を入れ替えることは防げません（署名はファイル名を含みません）。
- 秘密鍵ファイルかパスフレーズを失うと、復号できなくなります。秘密鍵のバックアップを別の安全な場所に保管してください。
